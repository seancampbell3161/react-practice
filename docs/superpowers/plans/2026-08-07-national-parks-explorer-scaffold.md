# National Parks Explorer Scaffold — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold App 1 of the React practice curriculum — "National Parks Explorer" — a working Express+TypeScript API and a bare Vite+React+TypeScript frontend shell, plus assignment/index READMEs, so the user can build the React frontend themselves.

**Architecture:** Two independent npm projects under `01-national-parks-explorer/`: `api/` (Express, in-memory data, two GET endpoints, supertest) and `web/` (Vite React-TS template trimmed to a blank placeholder page, Vitest + React Testing Library configured but no tests pre-written). No shared code between them, no database, no build tooling beyond what each project needs on its own.

**Tech Stack:** TypeScript, Express 4/5 + cors, tsx (dev runtime), Vite, React, Vitest, supertest, @testing-library/react, npm.

## Global Constraints

- TypeScript everywhere (frontend and backend) — from `docs/superpowers/specs/2026-08-07-react-practice-curriculum-design.md`.
- Plain CSS only, no CSS frameworks or CSS-in-JS.
- Plain `fetch()` only — no axios or other HTTP libraries (applies to the user's future frontend code, not this scaffold).
- npm as the package manager.
- In-memory data only — no database.
- No pre-written feature UI: the frontend ships as a blank placeholder page. Only infrastructure/config is scaffolded; the user writes all components, hooks, and state.
- API runs on a fixed port `4001`; web runs on Vite's default `5173`. CORS is enabled on the API for local dev.
- Testing: Vitest on both sides — supertest for the API, React Testing Library for the frontend. The API ships with a worked-example test suite for both endpoints. The frontend ships with test tooling configured (`npm test` works) but zero pre-written tests — that's part of the user's practice.

- [ ] **Step 1: Write the README**

Create `01-national-parks-explorer/README.md`:

```md
# National Parks Explorer

Your first React practice app. The API is already built and running; your job is to build the frontend that consumes it.

## Goal

Fetch and display a list of national parks. Clicking a park shows its full detail. This app is entirely read-only — no forms, no writes — so you can focus on the fetch → loading → render cycle.

## Running it

```bash
# terminal 1
cd api
npm install
npm run dev   # http://localhost:4001

# terminal 2
cd web
npm install
npm run dev   # http://localhost:5173
```

## Functional requirements

- On load, fetch `GET /api/parks` and render the list of parks.
- Show a loading indicator while the list is being fetched, and a readable error message if the fetch fails.
- Clicking a park fetches `GET /api/parks/:id` and displays its full detail (description, established year, size, activities) — with its own independent loading state, since it's a separate request from the list.
- Split your UI into at least two components (e.g. a list component and a detail component) so you practice passing data and event handlers via props.

## API contract

`GET /api/parks` → array of summaries:

```json
[{ "id": "yellowstone", "name": "Yellowstone", "state": "WY, MT, ID", "tagline": "America's first national park" }]
```

`GET /api/parks/:id` → full detail:

```json
{
  "id": "yellowstone",
  "name": "Yellowstone",
  "state": "WY, MT, ID",
  "tagline": "America's first national park",
  "description": "...",
  "established": "1872",
  "sizeAcres": 2219791,
  "activities": ["Hiking", "Wildlife watching", "Geysers", "Camping"]
}
```

`GET /api/parks/:id` returns a 404 with `{ "error": "Park not found" }` for an unknown id.

## Concepts to practice

- `useState` — tracking the park list, the selected park's detail, loading flags, and error state
- `useEffect` — fetching on mount, and re-fetching detail when the selected id changes (dependency arrays)
- Conditional rendering — loading / error / empty / loaded states
- Rendering lists with `.map()` and a stable `key`
- Event handlers — clicking a park to select it
- Props — passing data and callbacks from a parent component down to children

## Stretch goals

- Add a text input that filters the visible list client-side as you type (a controlled input).
